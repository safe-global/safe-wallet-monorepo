# Plan: Safe UI, primitives and Spaces components

Spec: [spec.md](spec.md). Builds on [plan-phase-0.md](plan-phase-0.md), [plan-phase-1.md](plan-phase-1.md) and [plan-phase-3.md](plan-phase-3.md), including the Phase 3 Redesign section.

The user asked to put the Spaces building blocks (the table, the accordion, the widget and similar patterns) into the design system, and decided:

1. The shadcn components move to a `primitives` layer inside `packages/ui`, and Safe's own components live next to them in a `components` layer. One package, two subpath families: `@safe-global/ui/primitives/<name>` and `@safe-global/ui/components/<name>`. No second npm package.
2. The wallet stays untouched: nothing in `apps/web` or `apps/web-tanstack` changes. In `packages/views`, only the one-line re-export shims change, and only to point at `@safe-global/ui/primitives/…` (and `@safe-global/ui/utils`, `@safe-global/ui/hooks/*`, `@safe-global/ui/provider`). The wallet keeps importing `@safe-global/views/components/ui/*`.
3. The wallet adopts the new Safe components later, together with Phase 2.

## Goal

When this increment is done:

- `packages/ui/src/primitives/` holds the 52 shadcn components, their tests, `table.module.css` and their stories. `packages/ui/src/components/` holds the new Safe components, built only from primitives, Base UI, `cn` and the hooks. The move is a pure `git mv`: no moved file changes by a single line.
- Six Safe components exist, extracted from the Spaces UI as generic, domain-free shells: `data-table`, `widget`, `expandable-list`, `expandable-card`, `peek-collapsible` and `stat`. Each has a jest test, a story with fake Safe-flavoured content, a canonical export key, a docs page, a registry item and a card in the Components index.
- Each new component renders the same pixels as the wallet's current version for equivalent content, checked by a screenshot comparison inside the `apps/web` Storybook. The few deliberate differences are listed with their reason (see D9).
- The docs site shows two groups, Primitives and Safe components, in the sidebar and on the Components index. Every existing URL stays (`/components/<name>/`, `/preview/<name>/<story>/`).
- `git diff 2da6ff13.. -- apps/web apps/web-tanstack` is empty, and `git diff 2da6ff13.. -- packages/views` only touches the re-export shims.

## Scope

- `packages/views`: retarget the 52 component re-export shims in `src/components/ui/` to `@safe-global/ui/primitives/<name>`, one line each. The other shims (`ShadcnProvider.tsx`, `src/utils/cn.ts`, `src/hooks/use-{mobile,tablet}.ts`, `src/components/common/iconStroke.ts`) already point at keys that don't move. No other views file.
- `apps/design-system`: generators, registry, page coverage, the Components index and sidebar groups, six new pages, the Create presets (T3, T6).
- Root: `.codescene.yml` exclude patterns (T1) and the `.claude/skills/design.*` path mentions (T7, agent guidance, called out in the PR).

## Decisions

**D1. Two layers in one package.** `src/primitives/` is upstream shadcn code (semi-generated, managed with the shadcn CLI as before). `src/components/` is Safe's own composed components. The direction is one-way: a component may import primitives, `../lib/utils`, `../hooks/*` and Base UI; a primitive never imports from `../components/`. Lint (`no-restricted-imports` scoped to `src/primitives/**`) and `relative-imports.test.ts` enforce it. Shared code (`lib/`, `hooks/`, `provider.tsx`, `styles/`) stays where it is: it belongs to neither layer and its export keys don't change.

**D2. The move keeps every relative import valid.** `src/components/x.tsx` → `src/primitives/x.tsx` sits at the same depth, so `../lib/utils`, `../hooks/use-mobile` and `./table.module.css` resolve unchanged, and the stories' `../button` imports resolve unchanged from `src/primitives/stories/`. T1 is therefore a pure `git mv` with no content edit, which keeps history (`git log --follow`) and makes "no visual change" provable from the diff: `git diff -M --stat` shows only renames at 100% similarity.

**D3. Story locations, chosen so no wallet file changes.** Primitive stories move to `src/primitives/stories/`; Safe component stories go to `src/components/stories/`. Every wallet reference to `packages/ui` keeps matching:

| Wallet file (untouched)                                           | Reference                                                                    | After the split                                                                                                                                                                                     |
| ----------------------------------------------------------------- | ---------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `apps/web/.storybook/main.ts`, `apps/web/.storybook-vite/main.ts` | `../../../packages/ui/src/**/*.stories.@(js\|jsx\|mjs\|ts\|tsx)`, `**/*.mdx` | Matches both story folders                                                                                                                                                                          |
| `apps/web/.storybook/shadcn-stories.css`                          | `@source '../../../packages/ui/src/components/stories'`                      | The folder still exists (Safe component stories). Primitive story classes stay covered by `apps/web/src/styles/shadcn.css` `@source '../../../../packages'`, which already scans all of `packages/` |
| `apps/web/jest.config.cjs`                                        | `roots: […, '<rootDir>/../../packages/ui/src']`                              | Covers both layers; the new ui tests also run in the wallet jest, as today's do                                                                                                                     |
| `apps/web/tsconfig.json`                                          | `../../packages/ui/src/**/*.ts(x)`                                           | Covers both; `yarn workspace @safe-global/web type-check` type-checks the new files                                                                                                                 |
| `apps/web/scripts/generate-storybook-tests.cjs`                   | `packages/ui/src/**/*.stories.tsx`                                           | Matches; it only writes files when someone runs it (risk 5)                                                                                                                                         |
| `apps/web/src/tests/__tests__/storybook-local-images.test.ts`     | scans `packages/ui/src`                                                      | Matches                                                                                                                                                                                             |
| `apps/web/src/styles/generatedCss.test.ts`                        | `packages/ui/src/styles/*`                                                   | Unchanged path                                                                                                                                                                                      |

Story titles stay explicit, so the 93 primitive story IDs (`ui-button--…`) do not change. Safe component stories use the `Safe UI/<Name>` title prefix (IDs `safe-ui-datatable--…`), which no wallet story uses (the wallet uses `Components/…`, `Features/…`, `Pages/…`).

**D4. Export scheme.** `packages/ui/package.json` `exports`:

- `"./primitives/<name>": "./src/primitives/<name>.tsx"` for each of the 52 primitives (`overlay` → `.ts`). Canonical.
- `"./components/<name>": "./src/components/<name>.tsx"` for each Safe component. Canonical.
- `"./<name>": "./src/primitives/<name>.tsx"` for the same 52 primitives: **deprecated aliases**, frozen to today's list, removed in Phase 2. JSON has no comments, so the deprecation lives in the export test (`LEGACY_FLAT_KEYS`), `AGENTS.md` and `README.md`.
- Unchanged: `./utils`, `./hooks/*`, `./provider`, `./styles.css`, `./scoped.css`, `./tokens.css`, `./eslint`, `./package.json`.

Explicit keys rather than a `./primitives/*` wildcard, because `overlay.ts` breaks a single extension pattern and the test checks one key per file.

**Why the flat aliases must stay.** 53 test files mock flat keys: 46 in `apps/web` and 7 in `packages/views` (for example `jest.mock('@safe-global/ui/tooltip')` in `packages/views/src/components/common/AccountRow/__tests__/TruncatedText.test.tsx`). Without the keys, `jest.mock` throws "Cannot find module" and those tests fail, and they can only be fixed by editing wallet files. With the keys, the mocks keep working. That test proves the mechanism today: the code under test imports `@safe-global/views/components/ui/tooltip`, which re-exports `@safe-global/ui/tooltip`, and the mock applies (`yarn workspace @safe-global/web jest ../../packages/views/src/components/common/AccountRow/__tests__/TruncatedText.test.tsx`: 10 passed). The apps/web jest config has no `moduleNameMapper` or custom `resolver` for `@safe-global/ui`, so jest resolves the subpath through the package `exports` and keys the mock by the resolved file. After the split, the shim's `@safe-global/ui/primitives/tooltip` and the test's `@safe-global/ui/tooltip` resolve to the same `src/primitives/tooltip.tsx`, so the mock still applies. T2 re-runs all 53 files to prove it.

**Export tests** (`src/package-exports.test.ts`, rewritten):

- every non-test `.ts`/`.tsx` file in `src/primitives/` has exactly one canonical key, `./primitives/<base>` → `./src/primitives/<file>`; the same for `src/components/` with `./components/<base>`
- every key under `./primitives/` and `./components/` points at an existing file
- the flat keys are exactly `LEGACY_FLAT_KEYS` (the 52 names today), and each points at the same file as its `./primitives/<name>` key; no Safe component has a flat key
- a primitive and a Safe component never share a base name (the registry item names, docs URLs and preview routes are one flat namespace, D7)

**D5. `packages/views` shims.** Each shim changes its one line from `@safe-global/ui/<name>` to `@safe-global/ui/primitives/<name>`. `ShadcnProvider.tsx` (`@safe-global/ui/provider`), `utils/cn.ts`, `hooks/use-mobile.ts`, `hooks/use-tablet.ts` and `components/common/iconStroke.ts` already point at keys that don't move; they're checked, and left as they are. `packages/views/eslint-design-system.mjs` re-exports `../ui/eslint/design-system.mjs`, which doesn't move. No views test file changes (their flat-key mocks keep working, D4). The wallet still compiles the same file contents, because a shim resolves to the same moved file.

**D6. The Spaces accordion is a new composed component, not an `accordion` variant.** The SecurityHub list differs from the primitive in anatomy (separate card rows with a gap instead of `border-b` separators, an accent bar, a leading icon, a trailing slot, an inset muted body) and in its chevron (one icon that rotates, while `AccordionTrigger` hard-codes a down/up pair). A variant would mean editing a shadcn primitive and its look for every wallet caller, which this increment never does. So `expandable-list` is built on `@base-ui/react/accordion` directly (Root, Item, Header, Trigger, Panel), which gives keyboard support, `aria-expanded`, `multiple` and the `--accordion-panel-height` transition. `expandable-card` stays on the `collapsible` primitive, as the wallet's version does.

**D7. Registry.** Item names stay flat and unique: `@safe/button` for a primitive, `@safe/data-table` for a Safe component (the test in D4 makes a clash impossible). Primitives stay `registry:ui` (they land in the user's `components/ui/`, where shadcn users expect them). Safe components are `registry:component`, copied from `registry/safe/components/<file>` so the shadcn CLI writes them to the user's `components/` folder and rewrites `@/registry/safe/components/…` to their `components` alias. A Safe component's `../primitives/x` import becomes `@/registry/safe/ui/x` plus the `registryDependencies` entry `@safe/x`. The SC4 smoke test confirms the placement with `shadcn@3.8.5` and `shadcn@4.23.0`; if a CLI version places `registry:component` elsewhere, add an explicit `target: components/<file>` and record it. Item count: 57 → 63.

**D8. Docs site.** Content stays in `content/docs/components/<name>.mdx` for both layers, so every URL stays. The layer comes from the export key (no frontmatter field to drift):

- `src/scripts/paths.ts`: `componentNames()` reads the canonical keys only and returns `{ name, layer: 'primitive' | 'component' }`; flat aliases are ignored.
- `stories.ts`: reads both story folders; the Code tab and Usage imports use the canonical key (`@safe-global/ui/primitives/button`, `@safe-global/ui/components/data-table`), never a flat alias. The `@ui-stories` alias becomes `@ui-src` → `<ui>/src`, and generated previews import `@ui-src/<primitives|components>/stories/<name>.stories` (`next.config.mjs`, `tsconfig.json`).
- `props.ts`, `icons.ts`, `rules.ts`, `registry.ts`, `check-registry.ts`: take files from `componentNames()` and scan both folders.
- Sidebar: `scaffold-pages.ts` writes `components/meta.json` as `index`, `---Primitives---`, the 52 primitives, `---Safe components---`, the Safe components (Fumadocs separator syntax), each group alphabetical.
- Components index: `component-grid.tsx` renders two headed sections (Primitives, Safe components) with the same filter box; the filter searches both.
- `ComponentInstall` shows the canonical import and `shadcn add @safe/<name>`. `ComponentRules` shows nothing for Safe components (no lint rule names them), and their Props tables come from docgen as usual.
- Create: the component checkboxes are grouped the same way; the Data display preset adds `data-table`, `widget` and `stat`.
- `pages.test.ts`: a page per canonical key, the meta.json groups match the layers, no name appears twice.

**D10. Component APIs (platform-neutral names, cva for variants).**

- **`data-table`**: `DataTable<T>` with the `PaginatedDataTable` props unchanged (`columns`, `rows`, `getRowKey`, `getRowClassName`, `renderRowDetail`, `onRowClick`, `pageSize`), `DataTableColumn<T>` and `ColumnWidth` types, and `DataTableCard` (the `TableCard` surface, exported from the same file because it only exists to frame a table and its states). ## Risks

1. **A flat-key consumer we didn't see.** Anything importing `@safe-global/ui/<name>` keeps working through the aliases, so the risk is only on removal (Phase 2). The export test freezes the list so nobody adds to it.
2. **CSS module class names change with the path.** `table.module.css` moves, so a generated class name that includes a path hash may change in the wallet bundle. Styles are identical; jest snapshots use `identity-obj-proxy`-style names. T8 screenshots cover it.
3. **Wallet CSS grows.** `apps/web/src/styles/shadcn.css` scans all of `packages/`, so utilities used only by the Safe components land in the wallet CSS. Visually inert; T8 proves only additions. Removing it needs a wallet edit (`@source not`), so it's left for Phase 2, when the wallet uses these components anyway.
4. **Argos on the wallet PR.** The new `safe-ui-*` stories appear in the `apps/web` Storybook, so Argos reports them as added screenshots that someone must approve. Expected; say so in the PR. Tag none of them `skip-visual-test` unless an animation flakes.
5. **`generate-storybook-tests.cjs`.** If someone runs it, it writes `*.stories.test.tsx` snapshot files for the new stories into `packages/ui/src/components/stories/`. That matches today's behaviour for primitives; not run in this increment.
6. **Name clash with `views` `DataTable`.** `packages/views/src/components/common/Table/DataTable.tsx` is a key/value list with the same name. Different import paths, so no technical clash; Phase 2 should rename the views one (e.g. `DataList`).
7. **Docgen on generics.** `DataTable<T>` is a generic function component; if `react-docgen-typescript` drops its props, `props.ts` handles it the way it handles aliased exports, and `props.test.ts` pins `columns`, `rows` and `getRowKey`.
8. **`registry:component` placement differs between CLI versions** (D7 fallback: explicit `target`).
9. **Parity of animations.** Replacing `motion` changes easing curves slightly during the fade; only end states are compared. Stated in D9.
10. **The new ui tests also run in the wallet jest** (`roots` include `packages/ui/src`). They must pass under both jest configs, as the primitives' tests do today; relative `jest.mock('../hooks/use-mobile')` paths work in both.
