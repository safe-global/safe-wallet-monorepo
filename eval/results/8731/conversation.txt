`safeParseUnits` unconditionally `console.error`s inside its `catch`. `${spender.address}-${index}` and `${limit.token.address}-${index}` both mix a stable id with the array index. If a spender or token address ever repeats (defensible for tokens — someone could grant two limits on the same token in principle, though the flow presumably disallows it), the index makes keys unique but also causes remounts when the row moves. Either use the pure address (relying on uniqueness) or use pure index — mixing is the worst of both. Given `spender.address` is guaranteed unique, `key={spender.address}` in `index.tsx` is enough.

**4. Empty‑policy fallback is ungrammatical** — `copy.ts:46`

`describePolicy({ spenders: [] })` produces `"You are giving spending limits."` (documented by the test at `copy.test.ts:103`). It's dead code in practice, but if it ever surfaces it will look like a bug. Either return `''` / no title, or short‑circuit with a neutral sentence.

**5. Minor duplication** — `AVATAR_SIZE = 24` (`SpenderSummaryCard.tsx:9`) and `TOKEN_ICON_SIZE = 24` (`LimitSummaryRow.tsx:9`)

Both hard‑code 24 for the same visual role (a small round icon in a summary row). Not worth a shared constant on its own, just noting the accidental duplication if a spacing pass ever unifies these.
