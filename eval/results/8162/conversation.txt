Nice consolidation — single-sourced address parsing, shared error overlay, three scanners now consistent. A few things worth a look:

### Potential issues

1. **Focus effect re-activates the camera even when the error overlay is shown** — `apps/mobile/src/features/Send/ScanQrSend.container.tsx:43-55` and `apps/mobile/src/features/ImportReadOnly/hooks/useScan/index.ts:15-28`.
   If the screen blurs while the lens shows the "Not a valid address" overlay (`errorMessage` set, `isCameraActive=false`), and then it regains focus, the effect unconditionally calls `setIsCameraActive(true)` and resets `hasScanned.current = false`. The user lands on a live camera *behind* the error overlay, and a new frame can fire scan logic again before they tap "Try again". Suggest gating on `!errorMessage`, or clearing `errorMessage` on focus so the two states can't disagree.

2. **`handledRef` isn't reset on focus cleanup** — `apps/mobile/src/features/WalletConnect/Wallet/hooks/useWalletConnectScan.ts:42-74`.
   Today it works because the address path uses `router.replace`, which unmounts the scanner. But if any future path keeps the scanner mounted (e.g. a back-nav from `/(send)/recipient`), `handledRef.current === true` will silently swallow every subsequent scan with no UX cue. Mirroring `pairingRef` and resetting in the cleanup (or in `onTryAgain` only, which is what it does today) is defensible — but worth a one-line comment that the invariant relies on `replace` unmounting the modal.

### Nits / cleanup

3. **Brittle test mocks** — `apps/mobile/src/features/ImportReadOnly/hooks/useScan/useScan.test.tsx:32-38`. The hook now calls `resolveScannedAddress`, but the test still mocks `parsePrefixedAddress` / `isValidAddress` transitively. Mocking `@/src/components/Camera/scannedAddress` directly would make the test less coupled to internal helpers.

4. **Inconsistent import** — `apps/mobile/src/features/Send/ScanQrSend.container.tsx:7` reaches into `@/src/components/Camera/useCameraPermissionFlow`, but the barrel at `apps/mobile/src/components/Camera/index.ts:4` already re-exports it. Use the barrel for consistency with the other Camera imports on line 6.

5. **`useScannedAddressToSend.ts:38` — `Date.now().toString()` for `scanTimestamp`**. Works, but if two rapid taps land in the same millisecond the param is identical and the route doesn't treat them as new. A monotonic counter (or `useRef` increment) would be deterministic. Low impact.

### Looks good

- Two refs (`pairingRef`, `handledRef`) for the two distinct burst-frame paths — clear and well-tested.
- Shared `resolveScannedAddress` + `INVALID_ADDRESS_MESSAGE` keep the address contract in one place; the wc-specific "Unrecognised QR code" copy stays local, which is correct (wc accepts a superset).
- Container tests assert the surfaces a user sees (overlay shown / heading hidden / chain-mismatch toast / nav call) rather than internal state. Good.
- `useScannedAddressToSend` cleanly separates "warn" + "navigate" so the in-Send vs header scanner can pick their nav mode.
