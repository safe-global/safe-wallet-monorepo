## 🍿 Summary

This PR fixes stale space data (accounts, members, contacts) that remained outdated across browser sessions until a full page reload. It introduces a shared RTK Query options constant `SPACE_REFRESH_OPTIONS` with `refetchOnFocus: true` and `refetchOnMountOrArgChange: 30`, applied to three space queries: space safes, members, and address book, plus the `AuthState` component. The change ensures that returning to the page or refocusing the window fetches fresh data, and that membership revocations (403/404 errors) clear stale member lists. This eliminates the need for manual refresh without introducing background polling.

## 🏗️ Architecture notes

A new module [`apps/web/src/features/spaces/hooks/refreshOptions.ts`](https://github.com/safe-global/safe-wallet-monorepo/blob/736fee80e60b7aa64a9a311726ac60836ae6afa7/apps/web/src/features/spaces/hooks/refreshOptions.ts) exports the shared constant. It is consumed by `useSpaceSafes`, `useSpaceMembers`, `useGetSpaceAddressBook`, and `AuthState`, where it is spread into the existing query options alongside skip logic. The `useSpaceMembers` hook additionally de-duplicates error handling: a 403/404 during refetch resets the member list to an empty array, preventing stale admin data from persisting. No polling is added; `refetchOnMountOrArgChange` is a staleness threshold checked only on new subscriptions, and focus-driven refetches keep last known data visible during fetch.
