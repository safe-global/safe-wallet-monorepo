Nice PR — copy, decisions and tests are well-documented, tests cover the first-entry / dismissal / seen path, and the boundary between the intro and the WA-3150 flow is drawn cleanly. A few things worth improving:

---

#### 1. `SpendingLimitPreview` is not `aria-hidden` — screen readers announce fake spender data

`apps/web/src/features/spaces/components/Policies/SpendingLimitIntroDialog/SpendingLimitPreview.tsx:63-95`

Only the `<Progress>` bar carries `aria-hidden`. The two spender rows and the token card are exposed to assistive tech, so a screen-reader user hears `Spender 0x867…a19b`, `1,500/Month`, `500 USDC remaining` — illustrative values presented as if they were a real limit. Since the whole block is described in the surrounding text (`DialogDescription` + the three explainers), adding `aria-hidden` on the outer container (or `role="img"` + a single `aria-label="Illustration of a spending limit"`) removes the noise without losing meaning.

#### 2. Multi-paragraph JSDoc/block comments across the new files

`SpendingLimitIntroDialog/index.tsx:10-14`, `38-41`, `43-44`; `SpendingLimitPreview.tsx:7-12`, `24-27`, `33`, `57-61`; `constants.ts:1-8`; `Policies/index.tsx:25-26`, `37-38`.

The repo rule (root `AGENTS.md` → General Principles) is "default to writing none … keep it to one line — never … write multi-paragraph comment blocks." Most of the new files carry 3–8-line JSDoc blocks; a lot of what's in them (what `EXPLAINERS` holds, why `PREVIEW_SPENDERS` has two entries, that `PreviewAddress` shows head + tail) is either obvious from the code or already in the PR description. Worth trimming to one line each — keep only the non-obvious *why* (e.g. the `useRef` for `initialFocus` comment is a good keeper).

#### 3. `PREVIEW_TOKEN.logoUri` fetches from `safe-transaction-assets.safe.global` in Storybook / tests

`SpendingLimitIntroDialog/SpendingLimitPreview.tsx:17`

The illustration issues a real network request every time the dialog renders — in Jest (no MSW handler for that URL) and in Storybook. It'll degrade gracefully via `TokenIcon`'s fallback, but you can drop the request entirely by pointing to `/images/common/token-placeholder.svg` (or letting `TokenIcon` render its placeholder by omitting the URL). Purely illustrative data has no reason to reach across the network.

#### 4. First-render read of `hasSeenSpendingLimitIntro` is always `false`

`Policies/index.tsx:12-13`

`useLocalStorage` returns `undefined` synchronously and populates from LS inside a `useEffect`. With `= false` defaulting, the first render treats "seen" as `false` regardless of the stored value — harmless for a click gate (nobody clicks before mount), but if you ever gate anything else on this flag during first render, the value will lie. Not a blocker; a one-line comment on the default (or a `?? true` biased-safe default) would make the intent explicit.

#### 5. Nit — `gap-2` on the primary `<Button>`

`SpendingLimitIntroDialog/index.tsx:86`

`className="w-full gap-2"` — `w-full` is layout, `gap-2` is internal spacing between text and icon and is common enough on icon buttons that ESLint may not flag it. If it does, the closer fix is a Button variant/size that already sets the gap rather than the disable escape hatch.

None of these blocks the PR — the biggest is the a11y one; the rest are cleanup.
