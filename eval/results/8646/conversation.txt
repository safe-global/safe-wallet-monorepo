### Code review

Solid, well-tested infrastructure. The scope-vs-URL split reads cleanly, tests hit the tricky RTK-Query loading states, and the trailing-optional `scope` on tx-sender keeps blast radius small. A few items worth surfacing before this ships as the foundation for WA-3150/3151/3152:

---

#### 1. `deployed: true` is hard-coded on the scope's SafeState

`apps/web/src/components/tx-flow/safe-scope/SafeScopeProvider.tsx:48-51`

```ts
const safe = useMemo<ExtendedSafeInfo | undefined>(
  () => (currentData ? { ...currentData, deployed: true } : undefined),
  [currentData],
)
```

Every scoped Safe is marked deployed regardless of what CGW reports. This matches today's assumption (counterfactual Safes are out-of-scope for WA-3146, per PR notes) but it's a load-bearing lie for any consumer downstream that branches on `safe.deployed` — including `runExecutionPreChecks`, which skips the STALE_NONCE check for undeployed Safes. Either (a) read the flag from `currentData` when CGW exposes it, or (b) add a `// TODO(WA-3147)` right on this line so the next person adding a Space-level entry point can't miss it.

#### 2. `runExecutionPreChecks` silently swallows the `_822` throw

`apps/web/src/services/tx/executionPreChecks.ts:137-142`

```ts
let sdk: ReturnType<typeof getAndValidateSafeSDK> | undefined
try {
  sdk = getAndValidateSafeSDK(scope)
} catch {
  sdk = undefined
}
```

The intent — "best-effort, skip the signature check when the SDK isn't ready" — is fine, but the bare `catch` also swallows the guard's `_822` throw. If a Space-level caller forgets to pass `scope` into `runExecutionPreChecks`, the guard's "throw + log" contract is silently downgraded to "no signature check runs at all," and the transaction proceeds without local signature verification. Consider distinguishing "SDK not ready" (skip) from "singleton reached under an active scope" (rethrow), e.g. re-throw when `hasActiveScope() && !scope`.

#### 3. `SafeScope` barrel forces a deep-import escape hatch on all callers

`apps/web/src/components/tx-flow/safe-scope/index.ts` re-exports `SafeScopeProvider`, which pulls ethers + protocol-kit into any consumer of the barrel. Two files already deep-import to dodge this (`safeCoreSDK.ts:24`, `web3ReadOnly.ts:9` with explanatory comments). This is a footgun: the next contributor who reads the barrel and imports `useSafeScope` from `@/components/tx-flow/safe-scope` regresses bundle size on any page that hook lands in. Consider dropping `SafeScopeProvider` from the barrel and requiring `import SafeScopeProvider from '.../SafeScopeProvider'` at the (one) mount site, so light-weight consumers can safely use the barrel.

#### 4. Bundle: global +1.24 KB with no user-facing surface yet

The bundle analyzer reports the global bundle grew by 1.24 KB even though this ticket ships no entry point (PR "Affected flows: None user-visible"). Worth sanity-checking that `SafeScopeProvider` and its ethers/protocol-kit deps aren't being pulled into the global bundle via the barrel or a stray import — since a scope should only be paid for on `/spaces/*` routes. See point 3 above.

#### 5. `_822` logs per call — noise budget

Already flagged in the PR body ("could be noisy in monitoring once a Space flow ships; revisit with WA-3150"). Fine to leave, but consider a first-hit-only dedupe at the module level before the first Space entry point lands, so the guard doesn't drown legit signal in the observability pipeline.

#### 6. Nit: `hasActiveScope()` is a plain module-scope counter

`apps/web/src/components/tx-flow/safe-scope/activeScope.ts` uses a module-local `let activeScopes`. This makes SSR-safe (Next.js) reasoning depend on the module being re-evaluated per request — which it isn't in the Next.js dev/prod bundle. In practice `getAndValidateSafeSDK` runs client-side only, so this is fine; worth a one-line comment reaffirming the client-only invariant on the counter, since it's the one piece of ambient state the guard depends on.

---

Nothing here blocks the merge for infrastructure-only scope; items 1 and 2 are the ones I'd want addressed before WA-3150 lights up the first real caller.
