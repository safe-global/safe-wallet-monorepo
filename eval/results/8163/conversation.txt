#### 1. The PR is about DRY, but the call-site pattern is duplicated 7+ times
Every consumer now has the identical block:

```tsx
<div className="flex min-w-0 items-center gap-1.5">
  <Typography variant="paragraph-mini" color="muted" className="truncate">
    {shortenAddress(address)}
  </Typography>
  <CopyAddressIconButton address={address} />
</div>
```

…in `AccountItemContent.tsx`, `AccountWidgetItem.tsx`, `SingleAccountItem.tsx`, `MultiAccountItem.tsx`, `SingleSafeRow.tsx`, `MultichainSafeRow.tsx`, `SafeCardLayout.tsx`, and `SafeCardReadOnly.tsx`. Consider a thin wrapper (e.g. `AddressWithCopy`) so spacing/truncation/typography stay aligned across surfaces. The Security Hub rows use MUI Typography while the others use the shadcn Typography — that drift will get worse over time.

#### 2. ARIA nesting in `SafeCardLayout`
`SafeCardLayout.tsx:47-118` wraps the row in `<button type="button" role="checkbox">` and now contains `CopyAddressIconButton` which renders `<span role="button" tabIndex={0}>`. Nested interactive roles inside a single interactive element is invalid ARIA and confuses assistive tech — same root concern as the original "button in button" comment, just one level up. Worth verifying with a screen reader, or consider moving the checkbox affordance out of the outer `<button>`.

#### 3. Accessibility — extra tab stops per row
Every account row gets a new `tabIndex={0}` element. For long lists (My accounts V2, Security Hub table, Spaces dashboard) keyboard users now pay two tab stops per row. Likely fine, but worth confirming the keyboard nav experience on the preview deploy was acceptable.

#### 4. Keyboard handler tests only `Enter`, not `Space`
`apps/web/src/components/common/CopyAddressIconButton/index.test.tsx:33-39` tests `Enter` but the component handles both `Enter` and `Space` (`index.tsx:14`). Add a `Space` case.

#### 5. Test coverage gap on touched surfaces
No unit tests added for `SingleSafeRow`, `MultichainSafeRow`, `SingleAccountItem`, `AccountItemContent`, `AccountWidgetItem`, or `SafeCardReadOnly` — they all gained a new interactive child, and the PR description acknowledges "nested-list copy buttons were verified via unit-level reasoning". A single happy-path "copy button is present + doesn't trigger row click" assertion per surface would close that gap cheaply.

#### 6. Minor — clipboard mock inconsistency
`AccountsWidget.test.tsx:85-94` re-defines `navigator.clipboard` inline, while `CopyAddressIconButton/index.test.tsx` and `MultiAccountItem.test.tsx` use `beforeAll`. Worth a small helper in `tests/test-utils` to avoid drift.
