There's a second `isMigrationToL2Possible` test suite that wasn't updated. `safeInfoBuilder()` defaults `version: '1.4.1'` (see `apps/web/src/tests/builders/safe.ts:37`), so after this PR:

- Line 78–80: `should not be possible to migrate Safes with nonce > 0` — `nonce: 2, chainId: '10'`, version defaults to `1.4.1`, chain 10 has `SafeMigration` deployed → helper now returns `true`, but the assertion is `toBeFalsy()`. **This test will fail on CI.**
- Line 82–84: also now duplicated with the assertions you added in `packages/utils`.

[Fix this →](https://claude.ai/code?q=In%20branch%20tongyao%2Fwa-1685-migrate-instead-of-cli%2C%20update%20or%20delete%20apps%2Fweb%2Fsrc%2Fservices%2Fcontracts%2F__tests__%2FsafeContracts.test.ts%20%E2%80%94%20the%20isMigrationToL2Possible%20describe%20block%20still%20asserts%20old%20nonce-based%20behavior%20and%20will%20fail%20because%20safeInfoBuilder%20defaults%20version%20to%201.4.1%20and%20isMigrationToL2Possible%20now%20gates%20on%20version%20not%20nonce.%20The%20canonical%20suite%20now%20lives%20in%20packages%2Futils%2Fsrc%2Fservices%2Fcontracts%2F__tests__%2FsafeContracts.test.ts%20so%20prefer%20deletion%20if%20fully%20redundant.&repo=safe-global/safe-wallet-monorepo)

### 2. Cast in `contractVersion.ts` is a smell that a narrower type would remove

`apps/web/src/features/security/data/scanners/contractVersion.ts:51-54`:

```ts
const canMigrateL2 = isMigrationToL2Possible({
  version,
  chainId,
} as Pick<SafeState, 'version' | 'chainId'> as SafeState)
```

The double-cast + comment saying "only these 2 fields are accessed" is exactly what a narrowed parameter type expresses in the signature. Consider:

```ts
export const isMigrationToL2Possible = (safe: Pick<SafeState, 'version' | 'chainId'>): boolean => { ... }
```

All four call sites (`UnsupportedMastercopyWarning`, `UnknownContractError`, mobile `Settings.container`, this scanner) still work — they already have `safe.version` and `safe.chainId` — and the cast in the scanner disappears. This makes the impact-on-caller minimum explicit at the type level rather than in a comment. Optional but worth doing while you're here.

### 3. Minor: doc a tiny caveat

The new JSDoc on `isMigrationToL2Possible` says "1.3.0 and 1.4.1"; worth noting that the version match is base-version only (build metadata like `+L2`/`+Circles` is tolerated via `isSupportedL2Version`), since that's the whole reason the customer Safes in WA-2874 now work. Nit — one extra line.

### Not blocking, just noting

- The behavior change from "1.1.1 nonce-0 → Migrate" to "1.1.1 → Use CLI" is correctly called out in the PR description as intended. Since `SafeMigration.migrateL2Singleton` doesn't support 1.1.1, this is the right call — a pre-1.3.0 Safe would have hit an on-chain revert before.
- No changes needed to the four consumers (`UnsupportedMastercopyWarning`, `UnknownContractError`, mobile `Settings.container`, `contractVersion` scanner) beyond the one already made — verified they all pass `version` on the safe object.
