Focused, well-scoped fix. Only a few minor points to consider — none blocking.

#### Nits / suggestions

- **`transaction-guards.ts:452`** — `isSafeMigrationCall` recomputes `SAFE_VERSIONS.flatMap(...)` and re-decodes the migration interface on every call. Since `isSafeUpdateTxData` is called from render paths (`confirmation-views/index.tsx:80`, `TxDetails/TxData/index.tsx:140`), consider hoisting the address list and the four selectors to module-level constants in `safe-migrations.ts`. Tiny perf win + clearer intent. [Fix this →](https://claude.ai/code?q=In%20apps%2Fweb%2Fsrc%2Futils%2Fsafe-migrations.ts%2C%20memoize%20the%20migration%20address%20list%20and%20the%20four%20migrate-method%20selectors%20at%20module%20scope%20instead%20of%20recomputing%20them%20inside%20isSafeMigrationCall%20on%20every%20call.%20Branch%3A%20tongyao%2Fwa-3261-restore-missing-version-upgrade-indicators-after-shadcn&repo=safe-global/safe-wallet-monorepo)

- **`transaction-guards.test.ts:205`** — the 1.5.0 test uses only the canonical selector/address. Consider adding one case for the zksync variant address to lock in the "any variant" contract now that the guard depends on it — otherwise a future regression that reverts back to canonical-only matching would still pass this suite.

- **`transaction-guards.test.ts:220`** — negative case is good, but currently only covers non-migrate calldata to a SafeMigration address. Symmetrical positive counter-example (migrate selector to a non-SafeMigration address) would fully pin down the two-part guard (address AND selector). Optional.

- **`MigrateSafeL2Review.tsx`** — LGTM. Removing the wrapper `<div>` aligns with `UpdateSafeReview` and is the correct fix for the `.step > .txCardRoot:first-child` selector. No logic change.

#### Behavioural tightening (worth calling out, not a bug)

The guard used to return `true` for any delegate call to the 1.4.1 SafeMigration `defaultAddress` regardless of calldata; it now requires calldata to start with one of the four migrate selectors. This is the intended tightening described in the PR — the `0xdeadbeef` negative test locks it in — but it does mean the UI now falls back to generic decoded data for any hypothetical delegate call to a SafeMigration contract using a different selector. Acceptable given the trust boundary (`trustedDelegateCallTarget && operation === DELEGATE`).

#### Test coverage

Adequate for the reported bug. Guard has direct unit tests; layout change is CSS-only and is caught by the visual test in the PR description.
