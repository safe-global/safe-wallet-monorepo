Solid, well-scoped E2E addition. Product changes are tiny and clearly justified. A few things to consider:

### Product code

**`DialogModal.tsx` — `accessible={false}` on the overlay `Pressable`** ([L32](https://github.com/safe-global/safe-wallet-monorepo/blob/tim/e2e-approval-editor-nonce-editor/apps/mobile/src/features/Send/components/DialogModal.tsx#L32))
Setting `accessible={false}` on the outer overlay `Pressable` removes the "tap outside to dismiss" action from VoiceOver/TalkBack — screen-reader users must rely on the Cancel button. Since Cancel is present, this is an acceptable tradeoff, but it's worth noting explicitly in the PR body (currently it's framed as a pure a11y improvement). On the inner container `Pressable` (L33–L43) the setting is genuinely benign — RN's `accessible={false}` there just prevents grouping so children remain individually announced.

### E2E setup (`draftEditorsSetup.ts`)

**Truthy-check in `waitFor`** ([L38–L41](https://github.com/safe-global/safe-wallet-monorepo/blob/tim/e2e-approval-editor-nonce-editor/apps/mobile/src/tests/e2e-maestro/setup/draftEditorsSetup.ts#L38-L41))
```ts
const value = read()
if (value) { return value }
```
`if (value)` rejects `0`, `''`, `false`. Fine today (both readers return objects), but as a generic helper this is a footgun. Consider `value != null` so future callers don't discover this by accident.

**Mixed `dispatch` sources** ([L61–L77](https://github.com/safe-global/safe-wallet-monorepo/blob/tim/e2e-approval-editor-nonce-editor/apps/mobile/src/tests/e2e-maestro/setup/draftEditorsSetup.ts#L61-L77))
`setupApprovalDraft` uses the passed-in `Dispatch` for `setupSendFlow` and `store.dispatch` for the RTKQ + compose calls. The comment explains the AppDispatch typing constraint, but since this is E2E-only and `store` is already imported, using `store.dispatch` throughout would be simpler. Minor.

**Setup-status marker only signals `ready`/`failed`, never resets to `idle` between runs**
`resetReduxForE2E` does call `draftEditorsE2eState.reset()`, but `setupApprovalDraft` calls `setupSendFlow` (which resets) before it flips to `ready`, so this is correct. Just calling it out — if that ordering ever changes, the marker could remain `ready` from a prior run.

### Maestro flows

**Spender text assertion** ([`verify-approve-amount.yml` L35](https://github.com/safe-global/safe-wallet-monorepo/blob/tim/e2e-approval-editor-nonce-editor/apps/mobile/e2e/utils/components/draft-editors/verify-approve-amount.yml#L35))
```yaml
text: '.*0x81Bd.*4fec.*'
```
Matches only 8 hex chars total — any address rendered short-form that happens to start `0x81Bd…` and end `…4fec` would pass. Given the spender is fixed and this runs after asserting the exact `_value`, the risk is negligible, but if you want a stronger assert you could match the full shortened form the UI actually produces (usually `0x81BdB0…14fec`).

**Nonce test — hardcoded `99999`** ([`send-nonce-editor.yml` L93](https://github.com/safe-global/safe-wallet-monorepo/blob/tim/e2e-approval-editor-nonce-editor/apps/mobile/e2e/tests/transactions/draft-editors/send-nonce-editor.yml#L93))
The "too low" branch depends on the live staging Safe's current nonce being `< 99999`. Extremely unlikely to ever be violated for a test Safe, but the test does silently couple to on-chain state — worth being aware of if this Safe ever ages.

### Tests

**Unit test coverage gap** ([`draftEditorsSetup.test.ts`](https://github.com/safe-global/safe-wallet-monorepo/blob/tim/e2e-approval-editor-nonce-editor/apps/mobile/src/tests/e2e-maestro/setup/__tests__/draftEditorsSetup.test.ts))
The `setupSendFlow` test doesn't assert `router.replace('/(tabs)')` was called. Since navigation is core to the setup's job (Maestro flows depend on landing on the home tab), a quick `expect(router.replace).toHaveBeenCalledWith('/(tabs)')` would round out coverage.

**No test for the `waitFor` timeout path**
`setupApprovalDraft`'s `waitFor('chain config', …)` and `waitFor('Safe SDK', …)` are the two places most likely to surface real E2E flakiness (SDK init timing). A test that returns `undefined` for either and asserts the failure marker/throw would catch regressions in that error path.
