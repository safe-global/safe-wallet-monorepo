### Claude PR Review

Solid, well-tested change. A few things worth tightening — none are blockers.

#### 1. `catch(() => [])` swallows every error, not just permission denial

`apps/tx-builder/src/hooks/useKnownAddresses.ts:33`

```ts
request = sdk.safe.requestAddressBook().catch(() => [])
```

The comment above says "Rejected permission throws PermissionsError (4001)" — but the `catch` treats any thrown value the same way. SDK bugs, iframe/postMessage timeouts, malformed responses, or a future non-4001 error code all collapse to "no contacts", indistinguishable from the granted-but-empty case. Because the promise is cached, that empty state also survives the entire session. At minimum, gate on the 4001 code and log/rethrow otherwise so real bugs are diagnosable:

```ts
request = sdk.safe.requestAddressBook().catch((err) => {
  if (err?.code !== 4001) console.warn('[tx-builder] requestAddressBook failed', err)
  return []
})
```

This also gives you the signal you need for the follow-up "distinguish rejected vs empty" empty-state you already flagged in the description.

#### 2. State-update after unmount

`apps/tx-builder/src/hooks/useKnownAddresses.ts:37`

```ts
request.then(setAddressBookItems)
```

If a user closes the app frame (or the AddressInput unmounts) between `loadAddressBook` firing and the promise resolving, this calls `setAddressBookItems` on an unmounted component. React 18+ tolerates it silently, but a small mounted-ref guard keeps this clean and future-proof:

```ts
const mountedRef = useRef(true)
useEffect(() => () => { mountedRef.current = false }, [])
// ...
request.then((items) => { if (mountedRef.current) setAddressBookItems(items) })
```

#### 3. Stale contacts on Safe switch (edge case)

`useKnownAddresses` filters the derived `knownAddresses` by `chainId` only, but the cache key is `${chainId}:${safeAddress}`. If the Safe context changes and the dropdown is not opened yet, `addressBookItems` still holds the previous Safe's data until `loadAddressBook` runs again. Unlikely inside Tx Builder (single-Safe per session), but it means "the derived list is authoritative for the current Safe" isn't quite true. Consider filtering by safeAddress too, or resetting `addressBookItems` when the cache key changes.

#### 4. `knownAddresses` recomputed every render

`apps/tx-builder/src/hooks/useKnownAddresses.ts:40`

```ts
const knownAddresses = addressBookItems.filter(...).map(...)
```

New array identity on every render → MUI's `options` prop churns → `filterOptions` re-runs. Wrap in `useMemo(..., [addressBookItems, chainId])`. Small book, small cost — but easy win.

#### 5. Fragile sticky-header offset

`apps/tx-builder/src/components/forms/fields/KnownAddressGroupHeader.tsx:11`

```ts
// cancels the listbox top padding so the header sticks flush
top: '-8px',
```

Hard-coded to MUI's current listbox `padding-top`. If MUI bumps that value (or theme spacing changes), the header will float or clip. Consider `top: 0` and instead zeroing the listbox's `padding-top` via `ListboxProps={{ sx: { pt: 0 } }}` on the Autocomplete — that keeps the coupling local.

#### 6. Minor

- `AddressInput.tsx:74` and `:133` shadow the imported `checksumAddress` with a local `const`. Pre-existing in one spot, propagated in the new code. Renaming (`checksummed`) removes a footgun for any future edit that needs the imported helper.
- `AddressInput.tsx:203` — `Children.count(params.children)` still works, but `React.Children` is legacy API. `Array.isArray(params.children) ? params.children.length : 0` reads clearer.

#### Tests
Coverage is good — hook, component, and the To-Address submission flow all exercised. Two suggestions:
- Add a case where `loadAddressBook` runs but the promise resolves *after* unmount, to lock in the fix from #2 above.
- Add a filter case for a fully-checksummed address input; currently only lowercase slices are tested.
